# AL Ops: business transformation site (draft)

Static site built from `../content/Business Transformation Website  Positioning & Content (1).md` (revised direction, 30 Sep 2026).
Transformation first, technology in service: the business-facing pages follow that document; the technical, trust and legal detail
from the earlier `Enterprise AI Website Blueprint.md` is kept as secondary pages for evaluators.
No framework and no runtime dependencies. Pages are generated by `build.py` (Python 3.8+).

## Build and preview

    python3 build.py                # pages, assets, and each 3D still whose scene changed
    python3 build.py --still        # force the 3D stills to re-render
    python3 build.py --no-still     # skip the 3D stills (e.g. on a machine without Chrome)
    python3 -m http.server 8000     # then open http://localhost:8000/

Preview through a local server, not by double-clicking files: links use clean `folder/` URLs as the blueprint specifies.
With `python3 -m http.server` the contact and documentation forms will show the failure box on submit, because `/api/contact` only exists
under `wrangler` (see Deploy below). Use `npx wrangler dev` from the repo root to test form submission.
Edit copy, structure, CSS and JS in `build.py`; the build overwrites every generated file and removes pages it no longer produces.
The 3D stills are rendered by headless Chrome with software WebGL (found automatically on macOS, Windows and Linux, or set
`CHROME_PATH`). The build fingerprints each scene (`SCENES` in `build.py`) in a `.hash` file next to its still and only re-renders
a still when its scene or the shared runtime changes; without Chrome it says so and keeps the existing image.

## Cookie consent

Every page carries a bottom banner (Accept all, Reject all, Manage preferences) and a preferences dialog, both emitted by `page()`.
The choice is stored in `localStorage` under `consent` as `{"v":1,"analytics":bool,"ts":ISO}`. Bump `CONSENT_VERSION` to ask everyone again.
The footer link "Your privacy choices" (`data-consent-open`) reopens the dialog; without JS it goes to the privacy notice.
PostHog loads only when the stored choice has `analytics: true` and `POSTHOG_KEY` is set. Withdrawing consent opts out, deletes the
`ph_*` cookies and storage keys, and reloads the page. Session recording is disabled. With an empty key the Analytics row is not shown.

## Deploy (Cloudflare)

Workers with static assets, configured by `wrangler.jsonc` at the repo root. `.assetsignore` keeps the sources (`build.py`, this README) unserved,
and the build writes `_headers` with basic security headers.

- Workers Builds build command: `cd transformation && python3 build.py --no-still` (CI has no Chrome, so the committed stills are kept)
- Deploy command: `npx wrangler deploy`
- Secrets, not committed: `npx wrangler secret put SHEETS_WEBHOOK_URL` and `npx wrangler secret put SHEETS_SECRET`
- Local: put the same two values in a `.dev.vars` file at the repo root, then run `npx wrangler dev` from the repo root

## Form storage (Google Sheet)

The forms POST JSON to `/api/contact`. The worker validates it, drops honeypot hits, and forwards it to a Google Apps Script web app that
appends a row per submission. Setup steps are in [../deploy/google-sheets/README.md](../deploy/google-sheets/README.md).

## Design system

Oceanic editorial system (revised 6 Oct 2026), on a Palantir-style layout: deep-sea base `#03141E` with foam text `#EAF6F4`,
secondary `#B4D0D4` and muted `#7FA2AB`, hairline rules `#14394C`, and one seafoam accent `#5EE0CF` for buttons, current navigation
and markers (`#0B6F6A` on light backgrounds). Square corners throughout. Tinted sections invert the active theme, so the dark site
alternates deep water and shallows `#E3F0EE` bands and the light theme does the reverse. Inter Tight (SIL OFL) for display and body,
IBM Plex Mono for labels. Fonts are self-hosted in `assets/fonts/`; the Satoshi and General Sans files from the earlier palette are no
longer referenced. The homepage hero draws an animated point-cloud swell on a canvas (static under reduced motion). Editorial layouts
keep the subtle scroll reveal that respects reduced motion.

## Illustrations

`assets/img/*.svg` are editorial illustrations drawn in code by `illustrations.py` (run `python3 illustrations.py`, then `python3 build.py`).
They follow the image brief: obsidian, slate, warm white and restrained blue; no cyan, glowing networks, dashboards, logos or metrics;
every image is captioned "Illustration" and has alt text. Placement: home (business in motion), financial services (customer experience),
supply chain (operations recovery), defense (readiness planning), utilities and transport (field infrastructure), company (growth).

The homepage illustration ("A business in motion") is an isometric 3D distribution centre at dusk, drawn with Three.js r186,
vendored in `assets/vendor/` (MIT, `LICENSE-three.txt`; bundled and minified from the npm package, no CDN). It is modelled at real
scale in metres: a tilt-up concrete building with five dock-high doors (seals, levelers, bumpers, dock lights), a grade-level
drive-in door, a glazed office, 53 ft trailers backed onto the docks, a sleeper tractor, an LPG counterbalance forklift, wrapped
EUR pallets, and 1.75 m workers in hard hats and hi-vis vests. Colours follow the site: deep-sea navy ground, seafoam accent bands,
trailer stripes and pins, warm lit windows and light pools. Its source is the `HUB3D` string in `build.py`, written to
`assets/hub3d.js` and imported only when the figure nears the viewport. `renderAt(t)` poses everything from `t` alone over a
12-second loop: the forklift takes a pallet from the outdoor staging bay through the drive-in door, the door pin turns into a
check, the next load is staged, a worker walks the pedestrian walkway, and traffic passes on the road. Decision cards (HTML over the canvas,
positioned each frame by projecting 3D anchors; `DECISIONS` in the module) show AI recommending and people deciding: a labour
rebalance approved by the shift lead, a low-confidence damaged-wrap flag overruled by the supervisor after inspection, and a door
swap for a late carrier approved by the yard lead. They are illustrative (the caption says so), hidden from assistive technology,
and summarised in a visually hidden list in the figure; on small screens only the newest card shows, in compact form. Visitors get a Pause/Play
button; reduced motion shows the frame at `STILL_T`. `assets/img/business-in-motion-3d.webp` is that same frame, rendered by the
build, and is used without JavaScript or WebGL, in print, and for the alt text.

The Growth page (`transformation/growth/`) plays a second scene the same way: `GROWTH3D` in `build.py`, written to
`assets/growth3d.js`, with its still at `assets/img/growth-room-3d.webp`. It is a project room at dusk in a flat night palette
(slate navy walls, periwinkle and paper-white cards, a city through the window). Over a 12-second loop a strategist adds a card to
the Evidence column of a wall board (Ideas, Evidence, Prototype, Pilot, Scale), two colleagues pass a sketch across the table, a
product lead brings pilot evidence in and takes it away again, and a prototype card is promoted to Pilot with a check. Its decision
cards: an early-segment insight approved by the product lead, a pilot price point overruled by the commercial lead, and a readiness
check approved by the sponsor. The Operations and Customer experience pages play two more scenes in the same night style:
`OPS3D` (`assets/ops3d.js`, still `assets/img/operations-line-3d.webp`): station 3 on a conveyor line stops for a tool change and
restarts, with cards for a torque-drift flag (approved by the line supervisor), a recovery plan (partly overruled by the planner)
and a restart check (approved by the operator); and `CX3D` (`assets/cx3d.js`, still `assets/img/customer-counter-3d.webp`): a customer
completes a pre-filled onboarding pack at a service counter while colleagues prepare the next case behind glass, with cards for the
pre-filled pack (approved by the service advisor), an address-mismatch flag (overruled by the team lead) and booking the setup call
(approved by the service advisor). The industry pages play three more: `FIN3D` (`assets/fin3d.js`, still `assets/img/financial-onboarding-3d.webp`), an onboarding
operations room where applications move across a pipeline display and one exception is cleared in staff review; `SC3D` (`assets/sc3d.js`,
still `assets/img/supply-network-3d.webp`), a planning room where a supply network display shows a delayed inbound route and supplier B
brought in, with a container port through the window; and `DEF3D` (`assets/def3d.js`, still `assets/img/readiness-room-3d.webp`), a
readiness planning room with a six-aircraft readiness board and a maintenance hangar through an interior window (generic aircraft,
no real units or systems). Each has three illustrative decision cards in the same pattern. The About page plays `INFRA3D` (`assets/infra3d.js`, still
`assets/img/field-substation-3d.webp`), an outdoor dusk scene: two field engineers beside a substation whose transformer T2 runs warm,
a metro crossing the viaduct and the city behind, with cards for the thermal flag, an overnight load switch (partly overruled by the
control room engineer) and the completed inspection. The seven night scenes share `assets/night.js` (the `NIGHT` string): palette, people, furniture,
the back wall with its window and city, lighting and camera. All scenes share `assets/motion.js` (the `MOTION` string): easing and tracks, materials and
primitives, the decision-card overlay, and the play/pause and off-screen behaviour. A figure names its scene in `data-motion`.


## Interactive components (progressive enhancement)

Every component renders its full content as HTML first; JavaScript only adds selection.

- Workflow run trace: one approved run and one denied action, stepped manually.
- Evidence record dialog: copy or download as text; deep link with `#evidence-record` on `platform/architecture/`. It carries a
  Hash ID (the head of a SHA-256 chain over the run's decision events, computed by the build from `EVIDENCE_EVENTS`), the MVDT
  (Minimum Viable Decision Trace) as JSON (decisionId, decidedBy, policyVersion, validAt, entities, inputs, signals, outcome,
  precedent, provenance; roles and stable IDs only), and a decision replay. "Replay decisions" steps through the six decisions and then
  recomputes every hash in the browser with Web Crypto (needs https or localhost) to show the chain matches. Values are synthetic.
- Mapping inspector, role-based permission view and deployment boundary views (tabs with arrow-key support).
- Model gateway routing demo and readiness self-check (scored locally, nothing sent).
- Platform stack on `platform/#stack` (for technical evaluators): a cross-industry reference stack adapted from the internal
  operating-system architecture (enterprise sources, solutions and users, nine layers L1 to L9, a control plane across all of them, the
  seven foundation services and the evidence record). No vendor names or build status are shown; availability is confirmed per release.
  "Follow one decision" highlights, in order, the parts each homepage decision passes through; the numbered step list is the text
  equivalent and the full stack renders without JavaScript. Data lives in `STACK_*` in `build.py`.
